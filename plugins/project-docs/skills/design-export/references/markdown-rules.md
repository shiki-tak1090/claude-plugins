# 設計書の Markdown 記法ルール

設計書は、ここで決めた記法の範囲だけで書く。ドキュメントのリポジトリは Obsidian で閲覧する前提なので、Obsidian のリンク記法も使ってよい。`design-export` スキルは、この範囲の記法を前提に Word や Excel へ変換し、内容が欠けていないかを機械的に照合する。範囲外の記法を使うと、変換で崩れたり、照合で誤検知が出たりする。

## 文書の先頭と末尾

テンプレートに指定がなければ、次の形にそろえる。

```markdown
# 文書タイトル

（この文書の目的を 1〜2 文で書く）

作成日：2026-05-01
版：v0.1

---

（本文）

---

## 変更履歴

| 日付 | 変更者 | 変更内容 |
|---|---|---|
| 2026-05-01 | — | 初版 |
```

- 版はファイル名ではなく文書内の「版」で管理する。ファイル名に `（v0.1）` を付けると、版を上げるたびにリンクが切れるため。
- 内容を変えたら、版を上げて変更履歴に 1 行追加する。

## 使ってよい記法

| 要素 | 書き方 | 備考 |
|---|---|---|
| 見出し | `#` 〜 `####` | `#` は文書タイトルに 1 回だけ使い、章は `##` から始める。下線式（`===` や `---`）の見出しは使わない |
| 段落 | 空行で区切る | 段落の途中で改行してもよい（変換後は 1 段落になる） |
| 箇条書き | `- ` | ネストは 2 段まで、半角スペース 2 つで字下げする |
| 番号付きリスト | `1. ` | 手順など、順序に意味があるときだけ使う |
| チェックボックス | `- [ ] ` | 受入条件など、テンプレートで指定された箇所だけに使う |
| 強調 | `**太字**` | `__` や `*斜体*` は使わない（識別子の `_` と紛れるため）。後述の注意を守る |
| コード・識別子 | `` `user_id` `` | テーブル名、カラム名、API パスなどは必ずこれで囲む |
| 表 | パイプ表（`\| 列 \| 列 \|`） | 1 行目を見出し行にする。セル内の改行は `<br>` だけ使ってよい。セル内の `\|` は `\|` とエスケープする |
| コードブロック | ` ``` ` で囲み、言語名を付ける | JSON、SQL、YAML などのサンプルに使う |
| 図 | ` ```mermaid ` | 構成図、画面遷移、ER 図、シーケンス図、状態遷移はすべて Mermaid で書く |
| 文書間リンク | `[[ファイル名]]`、`[[パス/ファイル名\|表示名]]` | Obsidian のリンク記法。Word や Excel では表示名（なければファイル名）の文字列になる |
| 画像 | `![[パス/画像.png]]` | 画面イメージなど、Mermaid で表せないものだけ。単独の行（または単独の箇条書き）に書く |

## 使わない記法

- `<br>` 以外の HTML タグ
- 引用（`>`）、脚注、定義リスト、Obsidian のコールアウト（`> [!note]`）
- YAML のフロントマター
- 文書の埋め込み（`![[別の文書]]`）。リンク（`[[別の文書]]`）にする
- 表の中の箇条書きやコードブロック（必要なら表の外に出す）
- 結合セル（Markdown では表せないため、同じ値を各行に書く）

## 強調の注意（日本語特有）

閉じの `**` の直前が括弧や句読点（`）` `」` `。` など）で、直後に文字が続くと、太字にならずに `**` がそのまま表示される。

- NG: `**質問文は固定（変更不可）**とする`
- OK: `**質問文は固定（変更不可）** とする`、または `質問文は **固定（変更不可）** とする`

閉じの `**` の後ろに半角スペースを入れるか、強調の範囲を括弧の手前までにする。

## 図について

- Mermaid の中に書いた ID や名称は、変換後は画像になり、文字としては照合できない。**図に出てくる ID や名称は、必ず本文か表にも書く。** 図は補足であり、図にしか書かれていない情報を作らない。
- 1 つの図で伝えることは 1 つにする。図の直前の文で、何を伝える図かを書く（例: 「本番環境で、利用者の通信がどこを通るかを示す」）。構成、データの流れ、処理の流れ、人の運用の流れを 1 つの図に混ぜない。
- 矢印の意味（通信、データの流れ、操作による遷移など）は、1 つの図の中でそろえる。
- 1 つの図に詰め込みすぎない。目安として、ノードは 15 個までにする。
- 図の中で改行するときは `<br>` を使う。`\n` は改行されず、そのまま `\n` と表示される（シーケンス図のメッセージで起きやすい）。

## 表について

- 列が 8 個を超える表は、Word では読めなくなる。テーブル定義や項目定義のような列の多い表は、その設計書を Excel で出力する前提で書く。
- 数値や ID の先頭の 0（`001` など）はそのまま書く。変換時に文字列として扱う。
