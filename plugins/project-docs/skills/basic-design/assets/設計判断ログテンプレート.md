**この文書は社内向けであり、納品物ではない。** 設計書には決めた結果を書き、ここには決めた理由を残す。後から「なぜこうなっているか」を調べるときと、前提が変わって見直すときに使う。

**書き方のルール**

- 判断したのは人である。AI が出した案やおすすめは「選択肢」として書き、「AI がそう言った」を理由にしない
- 判断した人が述べていない理由を、作成者（AI を含む）が推測で補わない。分からない項目は「未確認」と書く
- 「判断した人」は、設計情報の「設計を進める人」の立場（発注者、開発チーム）で書く。「本人」とは書かない。委任の範囲で AI が選んだものは「委任による選択（設計情報の委任 No.n）」と書き、委任した人が個別に承認したようには書かない。「回答の原文」は「—」とし、「理由」には比べた案と技術的な根拠を書く
- 「回答の原文」には、人が選んだ選択肢のラベルか、人が書いた答えを、言い換えずに写す
- 新しい判断が前の判断を置き換えたときは、前の判断の区分を「置き換え済み」にし、どの判断に置き換えたかを書く。設計情報の関係する行も同時に直す
- 再検討の条件は「将来見直す」ではなく、何が起きたら見直すかで書く（例: 植物が 1,000 件を超えたら）
- すべての判断を残さない。後から変えると影響が大きいもの、標準から外したもの、意見が割れたもの、制約で妥協したもの、暫定の対応だけを残す
- 開発標準の「採用する方針（決定記録）」にある判断は、ここに書き写さず、番号（`AD-01` など）で参照する
